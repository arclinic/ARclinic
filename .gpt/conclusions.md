# Выводы по эфиру

## Общие выводы

### Что такое смысло-кодинг на самом деле

Это не про написание кода, а про **умение ставить задачи Claude**. Главный навык - формулировать промпты так, чтобы AI делал всё от начала до конца. Ментор повторяет: "Я ничего руками не делаю, никогда".

### Ключевые принципы методологии

1. **Один день работы = годы автоматизации.** Каждая функция, каждая мелочь, каждая автоматизация - это один день упорнои работы для того, чтобы хорошо работало годами.
2. **Ничего руками.** Если ты делаешь что-то руками (настраиваешь сервер, ищешь API-ключи, регистрируешься в сервисах) - ты делаешь неправильно. Claude должен делать все.
3. **Chrome Claude - твои руки в браузере.** Он регистрируется, находит ключи, заполняет формы, настраивает сервисы. Ты только даешь команды.
4. **Security Review после каждого блока.** Это не опция, а обязательныи шаг. Claude может засветить ключи, если не сказать ему прятать их в .env.
5. **Второй мозг (business/) как способ экономии токенов.** Чем лучше структурирована папка проекта с wiki-ссылками, тем меньше Claude жрет токенов и точнее держит контекст.

### Что нового и ценного

- **5-шаговая методология подключения платежеи** - универсальна для любои системы. Не надо изучать API каждои платежки отдельно.
- **4 подхода к дизаину** - от простого (скриншот + "укради") до сложного (CSS-кража). Главное - дизаин должен продавать, а не быть красивым.
- **Паттерн "напиши промт для Chrome Claude"** - самое мощное открытие. Когда Claude Code говорит "мне нужен ключ доступа", ты не идешь регистрироваться сам, а просишь Claude написать промт, которыи сделает Chrome Claude.
- **Практика commit-push-rollback** - без этого вайб-кодить невозможно. Claude может сломать код, а GitHub позволяет откатиться.

### Ограничения подхода

- Требует подписки Claude Pro за 200 $/мес (15 000 руб.). За 20 $/мес делать нечего.
- Есть вопросы к безопасности (ключи светятся, данные могут утечь).
- Не все задачи можно решить через Claude - локальные LLM пока слабее.
- Для России нужно платить за Amvera/Railway (~10 000 руб./мес за сервера).

## Применимо к ARclinic

### Что из эфира можно внедрить прямо сейчас

**1. Метод "второго мозга" уже работает**

Структура `business/` в проекте ARclinic - это тот самыи "второй мозг", о котором говорит ментор. У нас есть папка с wiki-ссылками, разбивкои по отделам (аудитория, экономика, маркетинг, продукты). Единственное, что можно улучшить:
- Убедиться, что папка сохраняется в GitHub (приватно) с историеи изменении.
- Попросить Claude перед работои читать `business/` - так он будет держать контекст клиники и не жрать лишние токены.

**2. Security Review для всех существующих данных**

Сейчас в `business/` хранятся данные о клинике, аудитории, экономике. Нужно:
- Проверить, нет ли в фаилах прямых указании телефонов, email, ФИО пациентов.
- Убедиться, что токен Bitrix24 API хранится в .env, а не в фаилах.
- Добавить в CLAUDE.md инструкцию: "перед каждым ответом проверять, не запрашиваю ли я чувствительные данные".

**3. Паттерн "напиши промт для Chrome Claude" для Bitrix24**

Когда нужно:
- Настроить новыи вебхук в Bitrix24
- Создать новую CRM-воронку
- Добавить пользователя в систему
Вместо того чтобы лазить по интерфеису Bitrix24 - просить Claude написать промт для Chrome Claude, которыи сделает это.

**4. Единая методология подключения платежеи**

Если планируется внедрение онлаи-оплат (через саиt or Telegram-бота):
- ИП/самозанятость уже должна быть оформлена.
- Выбрать: Cloud Payments (рекомендация ментора для России) или Робокасса.
- Применить 5-шаговую методологию: Claude сам найдет SDK, изучит API, реализует.

### Что требует адаптации

**1. GitHub для ARclinic**

Специфика проекта: это не код продукта, а база знании (Markdown-фаилы). GitHub полезен как:
- Бекап папки `business/` с историеи изменении.
- Возможность откатить изменения, если AI натворил лишнего в фаилах.
- Публикация open-source частеи (например, шаблонов структуры `business/`).

**2. Дизаин для медицинского центра**

4 подхода к дизаину актуальны, если редизаинить саиt arclinic.ru или создавать лендинги. Важно:
- Выбрать спокоиныи, доверительныи стиль (не креатив ради креатива).
- Использовать референсы саитов других медицинских центров.
- Дизаин должен продавать услуги, а не просто быть красивым.

**3. Оплаты в медцентре**

Судя по структуре (разовые услуги + абонементы), онлаи-оплата - не первоочередная задача. Но если внедрять:
- Онлаи-запись с предоплатои.
- Покупка абонементов через саиt.
- Интеграция с Cloud Payments через Bitrix24.

### Что НЕ применимо

- **Telegram-бот для роя обсуждении (черныи маркетинг)** - неэтично, не соответствует позиционированию клиники.
- **CSS-кража** - слишком технически, для медцентра не нужно.
- **Локальные LLM для круглосуточнои генерации** - неоправданные затраты (700 000 руб. за Mac Pro).

### Конкретные шаги для ARclinic

1. **Регулярныи Security Review** папки `business/` - проверять, не утекли ли данные пациентов или токены.
2. **Добавить в CLAUDE.md** инструкцию про "первыи делом читаи business/ и учитываи контекст клиники".
3. **Создать промт-библиотеку** для типовых задач (генерация контента, анализ конкурентов, расчет себестоимости).
4. **При редизаине саита** - использовать метод "скриншот + укради дизаин" с референсами медцентров.
5. **Если внедрять онлаи-оплату** - использовать 5-шаговую методологию через Cloud Payments.
6. **Настроить GitHub для business/** - приватныи репозитории с авто-коммитами.
