# Сегментация клиентов ARclinic

## Определения сегментов

Для каждого клиента берётся окно в 365 дней от даты снимка. Считаются **не-проваленные** сделки (исключены стадии `:LOSE` и `LOSE`) по полю **BEGINDATE** (дата и время записи).

| Сегмент | Критерий |
|---|---|
| **Первичный** | 0 сделок в окне И 0 сделок за всю историю до окна |
| **Потерянный** | 0 сделок в окне, но были сделки ДО начала окна |
| **Развитие** | 1–5 сделок в окне |
| **Постоянный** | >5 сделок в окне |

## Технические правила

1. **Дата визита** — поле `BEGINDATE`, НЕ `DATE_CREATE` (дата создания сделки в CRM)
2. **Проваленные сделки** — стадии `:LOSE` и `LOSE` исключаются из подсчёта
3. **Глубина истории** — выборка сделок минимум с 01.01.2020 для корректного отделения первичных от потерянных
4. **Контакт без сделок** — `CONTACT_ID = null` или `"0"` исключаются

## Переходы между сегментами

Матрица переходов строится между двумя снимками (обычно конец предыдущего месяца → конец отчётного месяца). Для каждого клиента считается сегмент на обе даты, затем строится кросс-таблица.

### Ключевые метрики

- **Реактивация** — переход из потерянных в развитие/постоянные
- **Новые пациенты** — переход из первичных в развитие/постоянные
- **Отток** — переход из развития/постоянных в потерянные
- **Чистый отток** = ушло в потерянные − вернулось из потерянных

## Скрипты

| Скрипт | Назначение |
|---|---|
| `management/client_segmentation_transition.py` | Матрица переходов с кэшированием |
| `management/transition_report_may.py` | Отчёт по переходам за конкретный месяц |
| `management/list_lost_to_dev_16.py` | Список реактивированных клиентов со ссылками |
| `management/client_segmentation_cache.json` | Кэш сделок (BEGINDATE, STAGE_ID, CONTACT_ID) |

Для пересчёта за другой месяц — изменить даты снимков в `client_segmentation_transition.py`.
