# Архитектура проекта Arclinic

## 1. Общая концепция

**Модульный монолит** — одно приложение с четкими границами между модулями.
Каждый модуль может быть выделен в отдельный микросервис в будущем.

### Почему не multirepo? (рекомендация)

Вы выбрали multirepo, но для одного разработчика и малой клиники (<10 сотрудников)
**один репозиторий (monorepo)** практичнее:

- Единая сборка, тесты, линтер одной командой
- Общий код (shared) без публикации пакетов
- Нет боли с синхронизацией версий между репозиториями
- docker-compose поднимает всё сразу

Модули спроектированы так, что их можно выделить в отдельные сервисы потом.

## 2. Стек технологий

| Компонент | Технология | Обоснование |
|-----------|-----------|-------------|
| Язык | Python 3.12 | Выбран вами |
| Фреймворк | **Django 5.1** | Лучший для модульного монолита: ORM, админка, auth, сигналы |
| API | **Django REST Framework** | REST — стандарт, простой, зрелый |
| База данных | **PostgreSQL** | Подходит для любых объемов, JSON-поля, транзакции |
| Кэш / очереди | **Redis** | Кэш + Celery broker в одном |
| Фоновые задачи | **Celery** | Рассылки, отчеты, интеграции |
| Поиск | **PostgreSQL Full-Text Search** | На старте хватит, Elasticsearch — потом |
| Контейнеризация | **Docker + docker-compose** | Единое окружение для dev/prod |
| Веб-сервер | **Nginx + Gunicorn** | Классическая связка |
| Аутентификация | **JWT (djangorestframework-simplejwt)** | Stateless API, прост для интеграции |

## 4. Взаимодействие модулей

```
┌────────────────────────────────────────────────────┐
│                    Django App                      │
│                                                     │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────┐│
│  │ Marketing │  │Management│  │ Contact  │  │Accnt ││
│  │           │  │          │  │ Center   │  │      ││
│  └─────┬─────┘  └────┬─────┘  └────┬─────┘  └──┬───┘│
│        │              │             │           │     │
│        └──────────────┼─────────────┼───────────┘     │
│                       │             │                  │
│              ┌────────▼─────────────▼────────┐         │
│              │         Shared Code           │         │
│              │  (Base Models, Permissions)   │         │
│              └───────────────────────────────┘         │
│                                                     │
│  ┌──────────────────────────────────────────────┐   │
│  │  Celery (фоновые задачи)                     │   │
│  │  - Email рассылки    - Генерация отчетов     │   │
│  │  - Импорт/экспорт    - Интеграции с API      │   │
│  └──────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────┘
         │                    │
         ▼                    ▼
   ┌──────────┐        ┌──────────┐
   │PostgreSQL│        │  Redis   │
   └──────────┘        └──────────┘
```

**Правила взаимодействия:**
- Модули НЕ импортируют модели друг друга напрямую
- Общение между модулями — через сигналы Django или через shared-сервисы
- Для асинхронных операций — Celery задачи
- В будущем — выделение через REST API

## 7. Инфраструктура

**Разработка (локально):**
```
docker-compose up -d
# Поднимает: Django (с hot-reload), PostgreSQL, Redis, Celery worker
```

**Продуктив (рекомендация):**
1. VPS от Hetzner / DigitalOcean — $10-20/мес
2. Установка через Docker на один сервер
3. Резервное копирование PostgreSQL (pg_dump в S3)
4. Мониторинг через Sentry (бесплатный tier)

## 8. Дорожная карта (рекомендуемая)

| Этап | Что делать | Время |
|------|-----------|-------|
| 1 | **MVP Управление**: запись пациентов, CRM, расписание | 2-3 мес |
| 2 | **Учет**: касса, счета, зарплата | 1-2 мес |
| 3 | **Контакт-центр**: чаты, тикеты, интеграция | 1-2 мес |
| 4 | **Маркетинг**: рассылки, кампании, аналитика | 1-2 мес |
| 5 | **Интеграция**: телефония, мессенджеры, сайт | 1 мес |

> **Совет**: Начинайте с модуля **Управление** — это ядро клиники.
> Без записи пациентов и CRM остальные модули бесполезны.
